## 1. 현재 판단

최신 인증 후속: [카카오 OAuth·양방향 재인증·수단 연결/해제 HTTP](KAKAO-AUTH-IMPLEMENTATION.md) 구현, DB/HTTP 45개·Vitest 191개 통과, Preview 테이블 24개. 실제 공급자 설정·현재 사용자 조회/React UI·운영 준비는 남아 있다.

이메일 로그인 후속: [발급·검증·로그아웃 API](EMAIL-AUTH-IMPLEMENTATION.md), DB 공유 요청 제한·Resend adapter·HttpOnly 세션 쿠키 구현. DB/HTTP 통합 31개 통과, Preview 총 테이블 22개. 실제 메일 발송·카카오 OAuth·React 연결은 아직이다.

**화면을 전부 완성할 때까지 기다릴 필요는 없다. 핵심 쓰기 정책과 데이터 계약을 먼저 확정하면 백엔드 기반 작업을 시작할 수 있다.** 현재 도메인 타입·정책·파생 계산·저장 경계가 있어 출발점은 마련돼 있다.

다만 현재는 사용자 1명의 브라우저 기록과 가상 멤버 29명을 결합하는 프로토타입이다. 실제 시간 모드도 같은 시뮬레이터를 사용한다. 로그인, 실제 30명 배정, 서버 저장, 장치 간 동기화가 있는 서비스로 해석하면 안 된다.

가장 먼저 연결할 흐름은 **로그인 → 코호트 참여 → 인증 작성 → 홈·기록·피드에 같은 결과 표시**다. 졸업·공지·응원보다 이 경로의 정합성을 먼저 확보한다.

## 3. 확정된 규칙과 유지할 계약

현재 [policies.ts](../sixtysix-v2/src/domain/policies.ts)와 selector 기준:

- 기간 66일, 정원 30명, 면제권 최대 3회.
- 서비스 시간대 Asia/Seoul. 하루의 인증 마감은 다음 날 04:00.
- 마감 이후 12시간까지 어제의 늦은 인증 가능. 실제 쓰기 대상은 시간과 이미 채운 날을 함께 보고 계산한다.
- 연속 미인증 7일이면 휴면. 기록은 유지한다.
- 채운 날은 인증한 날과 면제권 사용일의 합집합이다. 실제 인증 수와 구분한다.
- 순위는 실제 인증 수 내림차순, 동률이면 연속 기록. 같은 값이면 공동 순위.
- late/simple/returning/streak/filled/status는 사실에서 파생한다.
- cohortDay는 접수 시 서버가 확정할 업무상 귀속일이므로 사실로 저장한다.
- 기간 종료(ended), 끝까지 참여(stayedToEnd), 66칸 채움(filled66), 면제 없이 66회 인증(perfect66)은 서로 다른 값이다.
- 복귀 후 화면은 별도 영구 상태가 아니라 done과 인증의 returning 판정을 조합한다.

이 규칙은 서버로 옮기더라도 동일한 fixture에 대해 같은 결과를 내야 한다. 정책 버전이 바뀌어도 과거 코호트가 다른 규칙으로 재해석되지 않도록 버전을 보존한다.

## 5. 백엔드 구조 초안

하나의 API 서비스와 관계형 데이터 저장소를 기준으로 책임을 나눈다. 실제 프레임워크·서비스 공급자·비용은 아직 선택하지 않았다.

| 책임 | 역할 |
|---|---|
| 인증 경계 | 세션을 검증하고 userId를 확정. 클라이언트가 보낸 소유자 ID를 신뢰하지 않음 |
| 명령 서비스 | 참여·인증·면제권을 검증하고 원자적으로 저장 |
| 도메인 규칙 | 정책 버전·서비스 시간대·귀속일·중복·성취 계산 |
| 조회 서비스 | 본인 진행, 권한을 적용한 피드, 코호트 통계·순위를 반환 |
| 파일 저장 | 실제 업로드를 도입할 때만 추가. 파일 접근도 인증 공개 범위에 맞춤 |
| 운영 | 오류 추적, 중요한 쓰기 요청 추적, 백업·복구 확인 |

클라이언트는 화면 상태를 표시하고 입력을 받는다. 서버가 시간, 사용자, 참여 자격, 인증 대상 일차, 실제 저장 결과를 최종 판정한다. 매일 휴면 값을 저장하는 작업은 기본적으로 필요 없다. 날짜와 사실로 계산할 수 있기 때문이다.

현재 WorldRepository는 동기식으로 세계 전체를 저장한다. 이를 HTTP로 그대로 바꾸지 않는다. AppProvider의 읽기·명령을 비동기 경계로 분리하고 서버에서 필요한 화면 데이터를 조회한다. 서버에 World 전체를 업로드하는 API는 만들지 않는다.

## 6. 데이터 모델 초안

| 엔터티 | 주요 데이터·제약 |
|---|---|
| User / Profile | 인증 주체 ID, 표시 이름, 계정 상태. 데모 ‘u-me’를 운영 ID로 사용하지 않음 |
| Habit | 이름·목표·대표 이미지·시간대 분류 |
| PolicyVersion | durationDays/capacity/passLimit/deadlineHour/lateWindowHours/dormancyDays/textMaxLength/timeZone의 버전별 불변 값 |
| Cohort | 서버 ID, habitId, 기수, startDate, policyVersion. 모집 상태·예약 규칙은 선결 결정 후 추가 |
| Membership | userId, cohortId, joinedAt. 같은 사용자·코호트 중복 제한. 동시 활성 참여 제한은 최종 정책에 맞춤 |
| DayEntry | membershipId, cohortDay, kind=checkin/pass, createdAt. UNIQUE(membershipId, cohortDay)로 두 종류를 함께 중복 방지 |
| Checkin 내용 | DayEntry에 대응하는 text, photoAssetId 선택값, visibility. 도메인 응답은 기존 Checkin 타입으로 투영 가능 |
| MediaAsset | 도입 시 소유자, 저장 키, 검증 상태. 업로드 완료·접근 권한 확인 전 인증에 연결하지 않음 |
| UserPreference | 공개 기본값 등 설정. 인증별 visibility는 해당 인증에 보존 |
| Reaction | 후속. fromMembershipId + checkinId 중복 제한과 같은 코호트 권한 |
| IdempotencyRecord | 사용자·명령 범위의 요청 키, 입력 요약, 응답. 같은 키 재시도는 같은 결과, 다른 입력 재사용은 충돌 |

DayEntry는 **DB 제안**이다. 기존 Checkin/PassUsage 의미를 합치려는 목적이 아니라 교차 중복을 DB에서 보장하기 위한 저장 구조다. 별도 테이블을 유지한다면 멤버십 잠금과 트랜잭션 등 동등한 교차 제약이 필요하다.

인증과 면제권에는 동일한 멤버십 잠금 순서를 적용한다. 날짜가 다른 면제권 요청도 동시에 들어오면 한도 3회를 넘을 수 있으므로 날짜별 UNIQUE만으로는 부족하다. 참여 정원도 잔여석 확인과 삽입을 한 트랜잭션으로 처리한다.

## 7. API 계약 초안 — 아직 미구현

| 영역 | 경로 초안 | 핵심 응답·검증 |
|---|---|---|
| 본인 | GET /v1/me | 프로필·설정·현재 멤버십. 세션 기준 |
| 모집 | GET /v1/cohorts?habitId=… | 서버가 제공하는 참여 가능한 코호트. 일정·정원·참여 정책 |
| 참여 | POST /v1/memberships | cohortId 입력. 중복·정원·모집 기간·인증된 사용자 검증 |
| 홈 | GET /v1/memberships/:id/home | serverNow, policyVersion, displayDay, state, todayStatus, progress, availability, action, cohort summary |
| 인증 | POST /v1/memberships/:id/checkins | text·visibility·photoAssetId 선택값, 예상 targetDay. 서버가 실제 귀속일 결정 |
| 면제권 | POST /v1/memberships/:id/passes | 예상 targetDay. 남은 한도·인증과 중복·권한·귀속일 검증 |
| 기록 | GET /v1/memberships/:id/record | 유효 1~66일 상태, 본인 인증, 통계. 본인 전용 |
| 피드 | GET /v1/cohorts/:id/feed?day=…&cursor=… | 같은 코호트 권한, 공개 인증만, 안정된 페이지 순서 |
| 멤버·순위 | GET /v1/cohorts/:id/members | 공개가 허용된 표시 이름·진행 요약·순위. 원시 비공개 인증 내용 제외 |
| 종료 요약 | GET /v1/memberships/:id/outcome | ended와 개인·코호트 성취를 구분. 졸업 화면의 데이터 기반 |
| 설정 | PATCH /v1/me/preferences | 공개 기본값 변경 |
| 사진 | 후속 업로드 계약 | 파일 선택 → 업로드 허가 → 업로드 → 검증 완료 → 인증 연결 |

쓰기의 createdAt, cohortDay, userId는 클라이언트 임의 입력으로 확정하지 않는다. 폼을 연 뒤 마감이 지나 targetDay가 바뀌었다면 TARGET_CHANGED로 최신 판정을 반환하고 사용자가 귀속일을 확인하게 한다. 서버가 다른 날짜에 조용히 접수하지 않는다.

쓰기 응답은 저장 사실 ID와 갱신된 availability/progress 또는 조회 갱신 키를 제공한다. 홈·기록·피드·순위를 함께 갱신해 화면 간 수치 차이를 막는다. 예시 오류 코드는 UNAUTHENTICATED, FORBIDDEN, ALREADY_FILLED, PASS_EXHAUSTED, COHORT_FULL, BEFORE_START, ENDED, TARGET_CHANGED, INVALID_TEXT, INVALID_MEDIA, IDEMPOTENCY_CONFLICT다. 코드와 HTTP 상태를 API 계약에서 확정한다.

## 8. 공개 범위와 서버 조회

- ‘나만 보기’ 인증의 본문·사진·자산 주소는 소유자에게만 반환한다. 클라이언트에서 숨기는 방식은 권한 통제가 아니다.
- 같은 코호트 구성원에게 일별 인증 여부·순위 지표까지 공개할지는 제품 계약에 명시한다. 현재 데모는 비공개 인증도 집계에 포함한다.
- 피드·직접 상세 접근·사진 접근·순위 조회에 동일한 권한 경계를 적용한다.
- 데모 데이터와 실제 사용자 데이터를 저장·집계·운영 화면에서 분리한다.
- 예약·탈퇴·코호트 종료 뒤 다른 멤버 기록을 계속 볼 수 있는 기간은 선결 결정 목록에 포함한다.

## 9. 진행 순서와 완료 조건

| 단계 | 작업 | 다음 단계로 넘어가는 조건 |
|---|---|---|
| B0 · 계약 확정 | P0 시간/면제/모집 규칙, 인증 방식, 공개 범위, 첫 서비스 범위 | 상태 전이표·쓰기 판정표·요청/응답·오류 사례를 문서로 고정 |
| B1 · 기반 | 서버 프로젝트, 환경 분리, DB 마이그레이션, 계정/세션, Habit/Policy/Cohort seed | 빈 DB부터 재현 가능, 실제 사용자 ID로 인증·비인가 차단 |
| B2 · 참여 | 코호트 조회·Membership 생성·정원/중복 통제 | 동시 참여에도 정원 초과·중복 활성 참여 없음 |
| B3 · 핵심 쓰기 | 인증·면제권·귀속일·중복 요청 처리 | 재시도와 동시 요청, 마감 전후, 면제권 한도 검증 |
| B4 · 조회 연결 | 홈·기록·코호트 피드·순위 및 비동기 UI | 같은 저장 결과가 모든 화면·재로그인·다른 기기에 일치 |
| B5 · 서비스 검증 | 실제 사진 필요 시 추가, 오류/복구, 접근 권한, 핵심 사용자 검수 | 두 계정으로 공개/비공개 확인, 백업 복구, 실패 재시도 확인 |
| 이후 | 졸업·탐색/예약 확장·인증 상세·응원·알림 | 사용자 흐름 우선순위에 따라 별도 범위 결정 |

디자인은 코호트·기록·인증 작성으로 확장하면서 B0 계약을 함께 맞추면 된다. B1~B3 착수에 마이·공지·졸업의 최종 시각 디자인까지 필요하지는 않다.

**현재 착수 판단:** B0와 T02 기술 기준·DB/API 계약 파일을 작성·검증했다. 다음은 인증 호환성 spike와 B1 서버 골격이다. 최소 모집 인원·참여 취소/이탈·보관 등 세부 권장안은 아직 확정 정책으로 표시하지 않는다.

## 10. 반드시 확인할 서버 수용 기준

- 다른 사용자 멤버십으로 쓰거나 비공개 본문·사진을 읽을 수 없음.
- 동일 날짜 인증 두 건, 인증과 면제권 동시 사용이 불가능함.
- 다른 날짜에 동시에 면제권을 요청해도 총 3회를 넘지 않음.
- 03:59:59 / 04:00 / 16:00 / 16:00 직후, 첫날·마지막 날, 서버 시간대에 동일 정책 적용.
- 네트워크 타임아웃 뒤 동일 요청 재전송 시 한 건만 생성됨.
- 폼 진입 뒤 귀속일이 바뀌면 기존 표시와 다른 날짜에 조용히 저장하지 않음.
- 코호트 마지막 자리 동시 참여 시 정원 초과 없음.
- 인증 저장 후 홈·기록·순위가 동일 사실로 계산됨. 면제권은 인증 수에 포함하지 않음.
- 서버 fixture 결과가 기존 selector의 확정 사례와 일치함.
- 로그아웃·재로그인·다른 기기에서 본인 기록이 유지됨. 데모 시계는 운영 데이터를 변경하지 않음.

# 육십육 V2 디자인 작업 계획과 진행 기록

> 최종 갱신: 2026-10-05
> 디자인 작업의 범위·결정·산출물·검수 결과를 이 문서에 계속 갱신한다.
> 제품 전체 현황: [PROGRESS.md](../PROGRESS.md). 정책과 범위: [V2-SCOPE.md](V2-SCOPE.md).

## 1. 개요

육십육은 같은 날 시작한 30명이 하나의 습관을 66일 동안 인증하는 모바일 웹이다. V2는 개인의 기록과 코호트의 움직임이 연결되는 경험을 만드는 프로토타입이다. 사용자 1명의 기록은 localStorage에 저장하고 나머지 29명은 결정론적 시뮬레이터로 구성한다.

이번 디자인 작업의 목표는 화면마다 달랐던 여백·글자·조작부를 재사용 가능한 규칙으로 묶고, 홈에서 그 규칙의 실제 사용성을 검증하는 것이다. 현재 단계는 **Figma 우선 설계**이며 앱 구현·배포는 별도 단계다.

### 디자인 계층

1. **Primitives**: 색상 원값, 크기 척도.
2. **Semantic tokens**: 배경·글자·간격·모서리의 역할. CSS 변수명과 연결.
3. **기본 컴포넌트**: 버튼·입력·토글·세그먼트·배지. 상태는 variant, 문구는 property.
4. **조합 패턴**: 헤더·하단 내비게이션·오늘 카드·코호트 요약·인증 카드.
5. **화면**: 컴포넌트 인스턴스를 조합하고 필요한 내용만 전달.

### 홈 화면

- 헤더 → 데모 시간 → 오늘 카드와 인증 행동 → 코호트 현황 → 오늘의 인증 → 하단 내비게이션.
- 큰 상단 사진을 줄여 인증 행동과 코호트 정보를 앞당긴다.
- 코호트 현황과 피드 제목의 위계를 맞추고 필수 설명은 14px 이상으로 배치한다.
- 주요 화면은 390px, 폭 비교는 360·430px로 만든다.
- 사용자는 진행 중인 데모 상태를 기준으로 구성하고, 이후 완료·휴면 등 추가 상태로 확장한다.
- 사진·아이콘은 프로젝트의 기존 자산을 사용한다. 화면 전체를 이미지로 평면화하지 않는다.

#### 이번에 적용한 제안

- 상단 200px 사진을 72×92px 썸네일로 축소하고 52px 인증 버튼을 오늘 카드 안에 포함했다.
- 오늘 카드 384px, 코호트 요약 184px. 높이 844px 검수 화면에서 인증 버튼과 코호트 현황 전체를 확인할 수 있다.
- 홈은 정보 밀도를 위해 섹션 사이에 기존 `space/inner` 12px를 사용했다. 공통 `space/block` 24px 기준 자체는 유지한다.
- 재사용 패턴 7개: Header, DemoTime, TodayCard, CohortSummary, CheckinFeed, BottomNav, HomeContent.
- 화면의 ScrollArea만 세로 스크롤하고 하단 탭은 그 밖의 형제 레이어로 분리했다. 아래 16px 고정 위치, 콘텐츠 끝 112px 여유 공간을 둔다.
- 탭 뒤 글자가 비치지 않도록 불투명 `color/bg/navigation`을 추가했다. 활성 탭은 코랄 아이콘과 굵은 라벨로 구분한다.
- 조작 크기 변수 `control/default=52`, `control/touch=44`, `toggle/track=26`을 추가했다. 추가 변수 4개는 **Figma 제안이며 CSS에 아직 등록하지 않았다**.
- 날짜와 수치는 캡처한 진행 중 데모를 기준으로 사용했다: 2026-09-08, D+23, 연속 9일, 채운 날 21일, 남은 날 45일, 오늘 인증 22명.

### 이번 범위 밖

- 앱 코드에 디자인 반영, 배포, 나머지 화면 전체 리디자인.
- 다크 모드, 새로운 브랜드 방향, 도메인 정책 변경.
- 실제 사진 업로드·로그인·실서비스 기능 추가.

## 7. 검수 체크리스트

- [x] 모든 기본군의 상태 개수와 variant 이름이 계획과 일치한다.
- [x] 문구를 component property로 바꿀 수 있다.
- [x] 색상·주요 간격·radius가 기존 변수에 연결된다.
- [x] 텍스트가 공통 스타일을 사용한다.
- [x] 원본 컴포넌트는 화면·검수 보드 밖에 있고 보드는 인스턴스를 사용한다.
- [x] 360·390·430px에서 가로 넘침과 텍스트 잘림이 없다.
- [x] 주요 조작 영역이 44px 이상이다. 비조작 Badge는 높이 32px.
- [x] 고정 하단 탭 위치와 스크롤 콘텐츠의 여유 공간이 구분된다.
- [x] 이미지·아이콘·텍스트·컴포넌트가 각각 편집 가능하다.
- [x] Noto Sans KR 임시 대체와 Pretendard 최종 검수 필요를 명시한다.

검수 결과: 32개 variant의 개수·속성, 조작 크기, 세 폭의 부모 영역 넘침 검사에서 오류 0건. 홈 콘텐츠의 텍스트 34개 모두 공통 스타일이며 14px 이상이다. 상태 보드와 세 폭 화면을 렌더링해 확인했고, 진행 막대의 폭·피드 카드 균등 너비·로고 선 두께·탭 가독성을 수정했다. 임시 웹 캡처는 자산 재사용 후 제거했다.

검수 한계: Figma의 레이아웃과 스크롤 속성까지 확인했다. 버튼의 실제 동작·브라우저 접근성·Pretendard 렌더링은 앱 반영 단계에서 검증한다. 이번 변경은 문서와 Figma이므로 앱 테스트를 다시 실행하지 않았다.

## 11. 홈 상태 확장 및 백엔드 준비 정리 — 완료

사용자 승인 범위: 인증 완료·연속 끊김·휴면·복귀 후·66일 종료 홈을 기존 디자인 시스템으로 확장하고, 기능 현황과 백엔드 전환 순서를 문서화한다. 앱·백엔드 구현은 이번 단계에 포함하지 않는다.

- 코드의 `getMemberState`, `getCheckinAvailability`, `getProgress`, 성취 판정을 기준으로 상태·문구·행동을 대조한다.
- 4개 주요 상태와 복귀 후 화면, 기존 진행 중 화면을 재사용 가능한 variant로 구성한다.
- 종료와 66칸 완주를 구분한다. 실제 앱에 없는 인증 수정·졸업 경로는 구현 완료처럼 표시하지 않는다.
- 예시 수치는 데모 facts를 상태별로 구성한 뒤 기존 selector로 계산한다.
- 완료 조건: Figma 상태 보드, 360·390·430px 검수, 기능 현황·데이터·API·백엔드 착수 조건 문서와 링크 갱신.

### 상태·행동 계약

| 상태 제안 | 도메인 판정 | 주 행동 | 보조 행동·후속 상태 |
|---|---|---|---|
| Ongoing | ongoing, 오늘 쓰기 가능 | 인증 남기기 → /checkin | 저장 성공 후 Done |
| Done | done, 오늘 실제 인증 있음 | 코호트 피드 보기 → /cohort | 내 기록 보기 → /record. 수정 기능은 현재 없음 |
| Broken | broken, 오늘 쓰기 가능 | 오늘 인증 남기기 → /checkin | 성공 시 done 및 returning 표시 |
| Dormant | dormant, 오늘 쓰기 가능 | 복귀 인증하기 → /checkin | 예시 17:00 접수는 Returned로 전환 |
| Returned | done + 오늘 인증의 returning | 코호트 피드 보기 → /cohort | 내 기록 보기. 기존 기록 유지, 연속은 1일부터 |
| Ended | ended, 쓰기 불가 | 66일 기록 보기 → /record | 졸업 화면은 후속 구현. 종료만으로 완주를 표시하지 않음 |

`/cohort`의 현재 기본 탭은 today이므로 ‘피드 보기’가 실제 피드 탭을 열게 하는 경로 계약은 앱 반영 시 보완한다. Figma 버튼은 동작 목적을 설계한 것으로 실제 앱 라우팅을 변경한 것은 아니다.

### 이번 결정

- 상태 비교 카드에서는 썸네일을 숨기고 상태·문구·수치·행동에 집중한다. 이전 `07_V2_HOME_PROPOSAL`은 비교 기준으로 유지한다.
- `remaining = 66 − filled`를 ‘빈칸’과 ‘칸’ 단위로 표시한다. 종료 뒤에도 남는 미인증 칸을 남은 기간으로 오해하지 않게 한다.
- 종료 시 현재 연속 대신 최장 연속, 코호트 오늘 현황 대신 종료 참여 요약을 표시한다.
- 완료/복귀 후에는 공개한 내 인증을 피드 앞에 두는 텍스트 미리보기를 만든다. 나만 보기 인증을 공개 피드에 넣지 않는다.
- 인증 수정 버튼은 만들지 않았다. 현재 명령·화면이 없으며 허용 시점과 집계 정책부터 결정해야 한다.
- 신규 변수는 추가하지 않았다. 기존 147개 변수와 공통 스타일·기본 버튼·배지를 재사용했다.

## 12. 백엔드 B0 명세 구체화 (2026-10-05)

## 13. T02 기술 구성·계약 파일 (2026-10-05)

[BACKEND-TECH-ARCHITECTURE.md](BACKEND-TECH-ARCHITECTURE.md)에 Node/TypeScript/Fastify/PostgreSQL 기준, 인증 후보의 필수 검증, 화면↔API↔도메인↔저장 경계와 구현 순서를 정리했다. [backend](../backend/README.md)에 업무 migration과 44개 API 작업의 OpenAPI를 작성했다.

- 검증: PostgreSQL 초기 스키마 생성·20개 거부 사례·UTF-16 경계, OpenAPI 구조/참조·입력 계약 14개 사례 통과.
- 설계 반영: 정확히 최종 접수 시각까지 허용, 이후 결과 확정. 재인증·연결 충돌·공개 모집 운영·탈퇴·비로그인 문의 계약 포함.
- 디자인 후속은 12장의 기능 화면 목록을 유지한다. API의 `availability`·`action`·오류 상태를 화면 동작 계약으로 사용한다.
- API 서버·실제 이메일/카카오 연결·운영 DB/배포는 아직 미구현. 다음은 **인증 호환성 검증과 서버 기반 구현**이다.

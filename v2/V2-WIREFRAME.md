## 1. 가장 큰 변경 — 하단 탭에 코호트를 넣는다

### 왜

V2 의 중심은 **가설 1, 코호트 소속감**이다 (`V2-SCOPE.md` 결정 1).
그런데 V1 하단 탭은 `홈 · 피드 · 기록 · 마이` 로, **코호트라는 말이 어디에도 없다.**

이 하나에서 진단 두 건이 파생됐다.

| 진단 | 실제로 벌어진 일 |
|---|---|
| P3-H 탐색 진입점 3곳 | 탭에 자리가 없어 헤더 아이콘 · 홈 섹션 · 졸업 CTA 세 곳에 따로 만들었다 |
| P3-G 랭킹 화면 밀도 낮음 | 「코호트 현황」이 독립 화면인데 9명 목록뿐이었다 |

피드와 랭킹은 **같은 대상(우리 30명)의 다른 뷰**다. 두 화면으로 나눌 이유가 없었다.

### 무엇을

```
V1   홈 · 피드 · 기록 · 마이
V2   홈 · 코호트 · 기록 · 마이
```

`코호트` 탭 안에 세그먼트 3개를 둔다.

| 세그먼트 | 무엇 | 흡수한 V1 화면 |
|---|---|---|
| 오늘 | 30명 중 몇 명이 오늘 인증했나 · 아직 안 한 사람 | 랭킹 상단 요약 |
| 피드 | 오늘의 인증 스트림 (**내 인증 포함**) | 코호트 피드 |
| 멤버 | 30명 전원 · 완주 페이스 순 | 코호트 랭킹 |

### 홈과 코호트가 겹치지 않나

역할을 이렇게 나눈다.

- **홈 = 나의 오늘.** D+N, 오늘 인증했나, 지금 눌러야 할 버튼 하나.
- **코호트 = 우리 30명.** 홈의 코호트 현황은 **요약 + 진입점**으로만 남는다.

## 3. 화면별 구조

### 3.1 홈 — 나의 오늘

```
AppHeader                       [육십육]        [탐색] [공지]
─────────────────────────────────────────────────────────
DemoClockBar   ★신설            데모 · 9월 8일 (D+23)   [날짜 바꾸기]
TodayHero                       D+23 / 66일 · 오늘 인증만 남았어요
                                연속 9 · 채운 날 21 · 남은 날 45
PrimaryCTA                      [인증 남기기]
HelpQuickMenu   (끊김·휴면일 때) [면제권 쓰기] [다시 시작하기]
─────────────────────────────────────────────────────────
CohortToday     ★살아 있음      30명 중 18명이 오늘 인증
                                ▓▓▓▓▓▓░░░░  60%
                                아직 안 한 사람 10명 · 늦은 인증 2 · 휴면 1
                                                        [코호트 보기 →]
CheerFeed       ★신설           내 인증에 붙은 응원 3
StoryRail                       오늘의 인증 (가로 스크롤)
NoticeBanner    ★공지 흡수      (있을 때만) 10/21 졸업식 안내
```

**바뀐 것**

- `DemoClockBar` — Gate 3 에서 `DemoClock` 을 만들었으므로 **화면이 그 사실을 밝혀야 한다.**
  V1 은 마이 깊숙이 숨겨 뒀다. 데모임을 숨기면 사용자 테스트에서 "왜 날짜가 안 바뀌죠" 가 나온다.
- `CohortToday` 의 18 은 이제 **시뮬레이터가 계산한 값**이다 (P1-C). 하드코딩이 아니다.
- `CheerFeed` — 내 인증에 시간차를 두고 응원이 붙는다. **가설 1 의 체감 지점**이다.
- 공지는 배너로 흡수. 있을 때만 나온다 (P3-G).

**fold(932px) 안에 들어가야 하는 것**: DemoClockBar · Hero · CTA · CohortToday 첫 줄.
행간 1.4 로 바뀌면서 화면당 30~40px 늘어나므로 **Hero 높이를 V1 426 → 약 390 으로 줄인다.**

### 3.3 기록 — 66칸을 눌러본다

```
DetailHeader / 기록
ProgressBoard   ★상호작용        11×6 = 66칸. 표시 방식은 유지
                                 누르면 아래 목록이 그 날짜로 스크롤
Legend
StatCards                        연속 9 · 채운 날 21 · 면제권 2
MonthMetrics                     9월 기록 6개
FilterChips                      내 인증 · 저장한 인증 · 배지
RecordList      ★진행판과 연동    선택된 날짜가 강조됨
```

**P2-F 해결 방식**: 6열 전환이 아니라 **진행판 ↔ 목록 양방향 연동**으로 간다
(`V2-SCOPE.md` 미결 항목에서 이미 이 방향으로 합의).
11×6 은 키 비주얼이라 건드리지 않고, 44px 터치 문제는 **타일을 누르는 게 아니라
타일이 목록을 움직이게** 해서 우회한다. 타일 자체의 히트 영역은 34px 그대로 두되
`aria` 로 목록 항목과 연결한다.

## 5-b. 05단계에서 결정한 것 (2026-09-10)

Figma `04_V2_DESIGN`.

### Hero 대비 — 「사진과 면을 분리」로 간다

`V1-DIAGNOSIS.md` §3.5 의 해결책이다. 두 안을 만들어 비교했다.

| | A안 — Scrim 강화 | **B안 — 사진과 면 분리 (채택)** |
|---|---|---|
| 방식 | 사진 위 텍스트 유지, Scrim 을 텍스트 블록 전체 높이(300px)까지 | 사진 200px 위 · 크림 면 아래. 텍스트를 사진 위에 올리지 않는다 |
| 대비 | 확보되지만 **코랄을 포기**해야 한다 | 코랄 `#C63A1E` on 크림 = **4.8:1**. 상징색을 D+23 에 그대로 쓴다 |
| 약점 | 사진마다 밝기가 다르면 또 틀어진다 | 사진 영역이 줄어든다 |

**채택 이유는 대비 수치가 아니라 구조다.**
디자인 규정 13.2 에 「슬라이드마다 이미지가 달라지는 경우 각 이미지에서 대비를 확인한다」가
이미 적혀 있었는데 지키지 못했다. 게을러서가 아니라 **사진마다 확인해야 하는 구조**였기 때문이다.
B안은 확인할 필요 자체를 없앤다. Scrim 튜닝은 사진마다 다시 해야 하지만 구조 분리는 한 번이면 끝난다.

Hero 높이 V1 426 → **약 390**. 행간 1.4 로 화면당 30~40px 늘어나는 만큼 줄였다.

### AvatarGrid 30칸 — 이니셜 원

아바타 사진 30장이 없다. 습관 이미지 6종을 돌려 쓰면 V1 이 하던 실수(습관 사진을 사람 얼굴로 쓰기)를 반복한다.

**이니셜 한 글자 + 상태 색**으로 간다. 59px 원 · 6열 × 5행.

| 상태 | 표현 |
|---|---|
| 인증 완료 | 코랄 채움 |
| 늦은 인증 | 코랄 채움 + 우하단 점 |
| 휴면 | 연회색 채움 + 달 아이콘 |
| 아직 | 흰 바탕 + 테두리 |
| 나 | 테두리 코랄 2px (바깥쪽) |

**모양으로 역할을 나눈다 — 네모는 날, 동그라미는 사람.**
66칸 진행판은 라운드 사각형이고 AvatarGrid 는 원이다.
상태를 색만으로 구분하지 않는 원칙(유지 목록)도 그대로 지킨다 — 점·아이콘·테두리를 병기한다.

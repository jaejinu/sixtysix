# 운영자 모집 생성·관리

2026-10-05 구현·로컬 검증 및 Preview DB 적용 완료. 기존 OpenAPI의 운영자 개설·시작 전 취소 계약을 연결했다.

## 동작

- 계정 → **모집 운영**(`/admin/cohorts`). 서버가 `operator_roles.role='admin'`을 확인한 뒤 목록과 개설 폼을 제공한다. 일반 회원·moderator는 403이며 운영 데이터/폼을 표시하지 않는다.
- 목록은 시작일·ID 내림차순 50개 단위로 조회한다. 취소·진행·종료된 기수도 포함하며 더 보기로 이어서 조회한다. 필요하면 기존 시작 판단을 수행한다.
- 개설 입력은 습관·기수 이름·시작일·모집 시작·정원·최소 시작 인원이다. 시작 시각은 서버가 해당 날짜 **한국 시간 04:00**로 계산한다. 모집 시작은 시작 시각보다 빨라야 하며 시작은 미래여야 한다. 정원 1~30명, 최소 인원 1~정원으로 검증한다. 최소 10명은 강제하지 않고 입력을 받는다. 기수 이름은 운영자 입력, ID는 서버 생성이다.
- 같은 습관/기수 이름 중복은 `COHORT_EXISTS`로 거부한다. 새로운 일정이나 이름을 입력하려면 새 요청으로 확인한다. 이미 개설한 모집의 수정은 이번 범위에 없다.
- 시작 전 취소는 사유를 입력하고 최종 확인해야 한다. 사유는 모집 상세에 공개되므로 화면에서도 이를 안내한다. 시작·취소 판단이 완료됐거나 시작 시각이 지난 코호트는 취소할 수 없다. 같은 성공 요청 재조회만 원래 결과를 반환한다.
- 생성/취소는 최근 **5분 이내 재인증**이 필요하다. 기존 계정 화면을 새 탭에서 열어 재인증하고 원래 화면에서 같은 요청을 다시 확인할 수 있다. 새 로그인 세션도 DB의 최근 인증 시각 기준으로 판단한다.

## 권한·원자성·동시성

앱 역할에 `operator_roles` 조회/변경이나 코호트 INSERT 권한을 직접 주지 않는다. migration 008의 제한된 SECURITY DEFINER 함수가 세션·계정 상태·admin 역할·최근 인증을 다시 검증한다. 역할 행을 읽기 잠금해 명령 도중 권한 삭제/변경이 완료되지 않게 한다. worker는 이 함수들을 실행할 수 없다.

- 생성은 코호트·감사·성공 멱등 응답을 같은 transaction으로 저장한다.
- 취소는 코호트 취소·사유·시작 판단·감사·outbox·성공 멱등 응답을 함께 저장한다. 한 부분이 실패하면 모두 rollback한다.
- 취소는 기존 참여 경로와 같은 코호트 잠금을 사용하고 잠금 획득 후 DB 시간으로 시작 경계를 검사한다. 동시에 들어온 참여는 취소 전 포함되거나 JOIN_CLOSED로 거부된다.
- 취소 outbox는 기존 `cohort.cancelled`/`cohort.launch:<id>` 형식이며 앱 내부 알림 worker에서 처리된다. 불필요한 참여자 계정 잠금 순환을 피하기 위해 참여 슬롯은 기존 다음 읽기/참여 시 정리한다.
- 성공 멱등 키는 일반 업무와 같은 `business` 범위를 사용한다. 같은 키·내용은 재조회하며 내용/경로가 바뀌면 충돌한다. 세션·역할·최근 인증은 재조회 시에도 다시 검증한다.
- 생성/취소 역시 계정별 새 요청 20회/분·120회/시간, 성공 결과 재조회 별도 60회/분 한도를 공유한다. UI는 429 대기와 네트워크 오류 후 동일 키·내용 수동 재시도를 지원한다.
- 감사에는 취소 사유 본문을 복사하지 않고 고정 action/reason, 대상 ID, 요청 키만 기록한다.

## API와 파일

- `GET /v1/admin/cohorts?cursor=…` — admin 목록, 재인증 불필요.
- `POST /v1/admin/cohorts` — 개설, 201.
- `POST /v1/admin/cohorts/:cohortId/cancel` — 시작 전 취소, 200.
- 쓰기는 세션·동일 origin/CSRF·UUID Idempotency-Key·요청 schema를 검사한다. 추가 필드와 호출자가 넣는 소유자 정보를 거부한다.
- DB: `backend/db/008_operator_cohorts.sql`; 서버: `sixtysix-v2/server/admin/`; 화면: `sixtysix-v2/src/ui/screens/AdminScreen.tsx`.

## 검증

- 별도 제한된 앱/worker 로그인으로 DB·HTTP **132개** 통과. 일반 회원/moderator/정지 계정 거부, 재인증·권한 회수 후 재조회 거부, 동시 중복 개설, 날짜/정원, 참여와 취소 경합, 감사 오류 rollback, 취소 → 알림, 요청 한도·페이지 이동을 검증했다.
- Vitest **259개 / 26개 파일**, API 계약 **21개 / 47경로**, 타입 검사·빌드 통과. 화면은 명시적 확인·동일 요청 재시도·권한 상실 시 목록/초안 제거·성공 후 목록 갱신 실패 분리를 검증했다.
- 360/390/430px 폼·개설 확인·재시도·취소 확인·권한 거부 **15개 모바일 검수** 통과. 가로 넘침·페이지 오류 없음. 확인 제목으로 초점을 옮겨 긴 목록에서도 변경 확인을 찾을 수 있다. 테스트 API 응답 기반이며 실제 공급자 검수는 아니다. 재현: `qa/scripts/admin-mobile.cjs`.
- admin 역할 검사를 제거한 변이를 테스트 3개가 감지했다. 복원 후 전체 DB 검증 통과.

## Preview 적용과 남은 운영 준비

Neon Preview에 migration **008**과 앱의 제한된 함수 실행 권한을 적용했다. 기존 001~007 checksum 유지. 26테이블·11함수 기준 앱/worker의 정확한 허용 권한 검증 통과. outbox 상태는 전부 0건이다.

**실제 운영자 지정·모집 생성·알림 처리·앱 배포·Production 변경·commit/push는 하지 않았다.** 가입한 첫 사용자를 자동으로 admin으로 승격하지 않는다. 공급자 준비 후 실제 로그인한 계정의 UUID를 확인하고, 관리자 DB 접근으로 승인된 계정에만 역할을 지정해야 한다. 앱 안의 역할 부여 API는 제공하지 않는다. Preview에는 실제 회원·모집이 아직 없으며 실계정 검수 준비 시 습관 카탈로그도 확인한다.

# 인증 코어 구현 기록

## 개요

2026-10-05. Better Auth 기본 구성에서 확인한 계정 연결 정책 불일치를 해결하기 위해 PostgreSQL 기반 서비스 계층을 구현한다. 계정 소유권은 `provider + subject`로만 결정한다. 카카오 이메일은 소유권 판단에 사용하지 않는다.

이번 단위는 검증된 공급자 증명 → 사용자·세션 생성 → 최근 재인증 → 명시적 수단 연결·해제다. 공급자 증명은 서버 내부에서만 등록하며 HTTP 입력을 그대로 신뢰하는 라우트는 만들지 않는다. 이메일 발송·OTP 검증·카카오 OAuth 전송 계층과 React 연결은 다음 단위다.

## 구현 기준

- 적용된 `001_initial.sql`은 수정하지 않고 `002_auth_core.sql`로 추가한다.
- 이메일 identity의 subject는 앞뒤 공백 제거·소문자 정규화 주소. 카카오는 공급자의 숫자 ID. 이메일 없는 카카오를 지원한다.
- 최초 로그인은 명시적으로 검증된 해당 identity만 조회한다. 참고 이메일로 기존 사용자를 찾지 않는다.
- 증명은 5분, 브라우저 문맥에 바인딩하고 한 번만 사용한다. link/reauth 증명은 세션에도 바인딩한다.
- 세션은 무작위 256비트 토큰, DB에는 SHA-256만 저장한다. 절대 만료 7일을 개발 기본값으로 사용한다. 갱신 정책은 공개 전 확정한다.
- 연결·해제에는 5분 이내 재인증이 필요하다. 세션·사용자 상태를 매 명령에서 다시 확인한다.
- 같은 사용자 수단 변경은 사용자 행 잠금으로 직렬화한다. provider/subject 잠금과 UNIQUE 제약으로 중복 소유를 방지한다.
- 마지막 사용 가능한 수단 해제는 거부한다. 정지·삭제 요청·익명화 계정의 세션은 거부한다.
- 해제한 수단은 비활성화하고 기존 소유권을 유지한다. 기존 계정이 명시적으로 다시 연결할 수 있으며 다른 계정으로의 이전은 구현하지 않는다. 해제 시 현재 세션을 제외한 해당 사용자의 세션을 회수한다.

## 검증 및 진행

완료한 코드: [`IdentityCore`](../sixtysix-v2/server/auth/identity-core.ts), [`002_auth_core.sql`](../backend/db/002_auth_core.sql), [독립 DB 통합 테스트](../backend/scripts/test-auth-core.mjs).

- PostgreSQL 16 통합 검증 **17개 통과**: 이메일 정규화·세션 hash, 이메일 없는 카카오, 양방향 명시적 연결, 브라우저/목적/세션 격리, 8건 동시 최초 로그인, proof/intent 재사용 거부, 타인 소유 수단 충돌, 동시 연결·해제, 만료·정지·삭제 요청, 로그아웃, 중간 실패 시 전체 rollback.
- 기존 Vitest **181개**, 프런트·서버 타입 검사 및 Vite 빌드 통과.
- 실제 Neon **Preview에 002 적용 완료**. 001 checksum 유지, 인증 테이블 3개 추가(업무 17개 + 인증 3개). 원격에서는 스키마·migration 이력과 기존 API를 읽기 전용으로 검증한다. 가짜 회원 데이터는 원격에 넣지 않았다.
- 동시 최초 로그인 중 다른 요청이 identity를 먼저 만든 경우 트랜잭션을 취소하고 사용자→identity 잠금 순서로 한 번 다시 실행한다. proof 소비도 취소되므로 중간 생성 계정이나 사용된 증명만 남지 않는다.

재현: 로컬 PostgreSQL의 CREATEDB 권한이 있는 연결을 `AUTH_TEST_DATABASE_URL`에 설정하고 `npm --prefix sixtysix-v2 run test:auth-core` 실행. 매 실행 새 임시 DB에 001·002를 적용하고 종료 시 그 DB만 삭제한다. 테스트는 원격 DB 주소를 거부한다.

## 다음 연결 단위와 한계

**후속 완료:** [이메일 로그인 API](EMAIL-AUTH-IMPLEMENTATION.md)의 발급·검증·DB 요청 제한·발송 adapter·세션 쿠키·로그아웃까지 구현했다. 아래 목록 중 재인증/연결 전용 OTP·카카오·화면·운영 준비는 계속 후속이다.

1. 이메일 OTP 저장·3회 시도 제한·분산 발송 제한·공급자 발송 adapter 및 서버 검증 → `recordVerifiedProof`. 증명 입력을 받는 공개 endpoint를 만들면 안 된다. 검증 목적·브라우저·세션은 발급 당시 서버 저장값을 사용한다.
2. 카카오 OAuth state·브라우저 바인딩·콜백 1회 소비·코드 교환·사용자 ID 검증. 참고 이메일은 identity 조회에 전달하지 않는다.
3. HTTP 인증 라우트에 Origin/CSRF·HttpOnly 세션 쿠키·로그아웃 쿠키 제거·오류 계약·요청 제한 연결. 현재 코어는 쿠키를 발급하지 않으며 로그인 라우트는 미구현이다.
4. 런타임 최소 DB 권한, 인증 감사 이벤트, 증명/만료 세션 정리 작업, 탈퇴 시 identity 개인정보 삭제·보관 정책. 이 조건들을 구현하기 전 공개 운영하지 않는다.
5. 메일 서비스·카카오 앱 설정 후 실제 공급자 E2E와 React 로그인 연결.

세션 7일 및 비활성 identity 소유권 유지 방식은 개발 기본값이다. 서비스 정책 확정 때 갱신한다. `auth_subject`는 app_users.id와 같은 내부 UUID 문자열로 사용하며 공급자 ID나 가짜 이메일을 넣지 않는다. Better Auth는 재현 테스트 의존성으로만 유지한다. 실제 메일 배달·카카오 로그인·공개 배포는 완료하지 않았다.

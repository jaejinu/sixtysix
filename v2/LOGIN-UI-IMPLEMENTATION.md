# 현재 사용자 조회·로그인 화면

## 개요

2026-10-05. 인증 API 다음 단계로 `/v1/me`, 이메일/카카오 로그인, 재인증·수단 연결/해제·로그아웃 화면을 연결한다. 실제 계정 화면은 `/login`, `/account`에 두며 기존 데모의 습관 기록·프로필과 섞지 않는다. 데모 온보딩 여부가 계정 화면을 막지 않게 한다.

## 구현 기준

- 서버는 쿠키 세션의 사용자만 조회하고, 정지·탈퇴 요청·만료·위조 세션은 401로 거부한다. 응답에는 마스킹된 로그인 수단·본인 프로필/참여만 포함한다.
- 브라우저는 같은 origin의 API를 호출한다. 세션 토큰은 JS 저장소에 저장하지 않고 HttpOnly 쿠키로만 관리한다. 쓰기 전 `/auth/context`에서 CSRF를 얻는다.
- 이메일 인증번호 입력, 만료·오답·429 대기·503·네트워크 실패, 재요청, 중복 제출 방지를 제공한다.
- OAuth query는 화면 안내에만 사용한다. 실제 로그인 상태는 항상 `/me`로 재확인하며 연결 complete는 서버가 소유권을 재검사한다.
- 연결 검증 완료 후 사용자가 최종 연결을 실행한다. 마지막 수단 해제·재인증 필요·다른 계정 수단 충돌을 구분한다.
- 기존 폰트·간격·입력·버튼 토큰을 재사용하고 360/390/430px에서 확인한다. 실제 기록 서버 연결과 공급자 실계정 검수는 후속이다.

## 진행

구현 완료. 원격 배포와 공급자 실계정 검수는 포함하지 않는다.

- `GET /v1/me`: 본인 프로필·마스킹된 로그인 수단·참여/현재 참여만 조회. 미인증·위조·정지·폐기 세션 거부, 응답 no-store.
- `/login`, `/account`: 이메일 OTP·카카오 시작, callback 결과 확인, 기존 수단 재인증, 명시적 연결 완료, 해제 확인, 로그아웃. 데모 온보딩 없이 접근 가능.
- 데모 마이페이지/온보딩에 계정 진입 링크 추가. 계정 화면에는 샘플 기록과 실제 저장의 차이를 표시한다.
- CSRF 선행 요청, 중복 제출 방지, 15초 네트워크 timeout, 자동 쓰기 재시도 금지. 60초 재발송 대기와 429 전체 요청 대기를 구분한다.

## 검증

- Vitest 204개, PostgreSQL/HTTP 통합 47개, OpenAPI 46개 경로·계약 사례 14개 통과.
- 프런트/서버 타입 검사, Vite 빌드, Vercel 로컬 Preview 빌드·API rewrite/SPA/함수 산출물 검사 통과.
- 모바일 360/390/430px × 로그인·코드 입력·계정·503 오류 12개 화면 검수: 가로 넘침 없음, 입력/버튼 44px 이상. 테스트 API 응답을 사용했으며 실제 공급자 E2E 검수는 아니다. 스크린샷에서 폰트·여백·줄바꿈을 확인했다.
- 운영 의존성 audit 0건. 개발 도구 의존성 5건은 별도 업데이트 대상이다.

## 문제 가능성과 후속 우선순위

1. 공급자 설정/실계정 검수: Resend 발신 도메인, 카카오 앱/redirect URI와 비밀값이 미설정이다. 실제 메일 수신·OAuth 왕복·재인증은 검증 전이다.
2. 배포 전 DB 권한: migration 계정과 런타임 최소 권한 역할을 분리한다. Preview DB를 Production에 재사용하지 않는다.
3. 업무 기능: 실제 코호트 모집·참여·기록 저장 API는 아직 연결되지 않았다. 다음 구현은 공개 모집 조회·참여 트랜잭션이다.
4. 운영: 감사 기록·만료 인증 데이터 정리·개인정보 삭제와 보관 정책을 구현해야 한다.
5. 개발 의존성: 기존 Vite/Vitest 계열 취약점의 영향과 호환성을 확인해 업그레이드한다.

위 항목 때문에 이번 완료를 실서비스 공개 준비 완료로 판단하지 않는다. 이번 작업에서 commit/push/공개 전환/원격 앱 배포는 하지 않았다.

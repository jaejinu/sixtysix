# Git 저장소 공개 전 확인

2026-10-05 사용자 질문에 따라 읽기 전용 점검했다. 저장소 visibility 변경·commit·push·배포는 하지 않았다.

## 결과

점검 범위에서 실제 비밀값은 발견되지 않았다. 소스 공개를 막는 자격 증명 노출은 확인되지 않았으며, 아래 공개 콘텐츠 범위를 받아들일 수 있다면 public 전환을 검토할 수 있다. 이는 서비스 운영 준비 완료나 모든 비밀값의 부재를 보증하는 감사가 아니다.

- 작업 트리의 Git 추적/추적 예정 경로 244개를 대상으로 텍스트 검사.
- 로컬에 존재하는 전체 Git ref의 33개 커밋에서 고유 텍스트 blob 211개 검사.
- 개인키 헤더, GitHub/AWS/일부 공급자 토큰 패턴과 현재 Preview DB 연결 비밀값·비밀번호·OIDC 토큰의 정확 일치 검사: 발견 0건. 값 자체는 출력하지 않았다.
- 2MB 초과 파일·바이너리는 텍스트 검사에서 제외했다. 원격에만 존재하고 로컬로 가져오지 않은 이력·Actions 로그·다른 저장소·새로 추가하는 파일은 이번 범위가 아니다.
- `.env*`, `.vercel`은 ignore되며 `.env.example`만 예외다. 실제 `.env`/`.env.local`·Vercel 연결 메타데이터가 ignore되는 것을 확인했다.

## 함께 공개되는 내용

기획/진행 문서, Figma 링크, 서비스 배포 주소, 프로젝트/리소스 식별자, 테스트용 예시 값, Git 커밋 작성자 정보도 보인다. 문서의 공개 범위를 줄이고 싶다면 선택적으로 정리한다. 이 식별자를 비밀키와 같은 것으로 간주하지 않는다.

앞으로도 실제 비밀키는 Vercel 서버 환경 변수/제외된 로컬 파일에 두고, push할 변경과 history를 확인한다. 코드가 공개돼도 브라우저에 DB/공급자 비밀키를 전달하지 않는 구조를 유지한다.

## 서비스 상태와 구분

소스 공개와 실제 서비스 공개는 별도다. 현재 인증 코드는 DB/가짜 공급자 테스트까지 검증했으며, 카카오·메일 실계정 검수·런타임 DB 권한 분리·감사·개인정보 정리는 남아 있다. 자동 배포가 연결된 브랜치에 push하는 작업도 이번 질문만으로 실행하지 않았다.

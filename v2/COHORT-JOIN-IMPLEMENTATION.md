# 공개 모집·참여 구현

## 개요

2026-10-05. 인증 다음 단계로 공개 모집 목록/상세와 참여·시작 전 취소를 실제 PostgreSQL에 연결한다. React `/recruitment`에서 서버 데이터만 사용하며 기존 데모 코호트와 분리한다. 원격 모집 생성·배포는 이번 작업에 포함하지 않는다.

## 구현 기준

- 기존 OpenAPI의 GET `/cohorts`, GET `/cohorts/:id`, POST `/memberships`, POST `/memberships/:id/cancel`을 구현한다.
- 사용자 → UUID 순 코호트 잠금. 잠금을 얻은 뒤 DB 시각으로 참여/취소 경계를 판정한다.
- 정원·모집 시작/마감·활성/대기 슬롯 1개·소유권을 서버에서 검증한다.
- 사용자별 멱등 키와 method/path/body hash, 성공 응답을 업무 변경과 함께 commit한다. 같은 키·다른 입력은 충돌, 같은 요청 재시도는 원래 성공 응답이다.
- 시작 시 최소 인원을 판정하고 결과와 outbox 이벤트를 한 번 기록한다. 발송 worker는 후속이다.
- 최소 인원은 코호트 설정값을 사용한다. 운영 기본값은 사용자 답변 전 확정하지 않는다.
- 기존 membership의 취소 사실을 지우지 않는다. 현재 UNIQUE(user,cohort) 계약상 취소한 동일 기수 재참여는 차단하며 화면에 알린다. 다른 모집 참여는 가능하다.
- 참가자 이름·ID·세션 등은 공개 모집 응답에 포함하지 않는다.

## 검증 계획

실제 DB에서 마지막 자리 경쟁·동일 계정 교차 참여·키 재시도/충돌·취소 경계·타인 취소·최소 인원 취소·슬롯 정리·트랜잭션 rollback을 확인한다. UI는 비회원·빈 모집·참여 대기·실패 후 동일 키 재시도·취소 확인과 모바일 배치를 검수한다.

## 진행

구현·로컬 검증 완료. 공급자 실계정 검수와 공개 운영 준비 완료를 뜻하지 않는다.

- 서버: `server/cohorts/service.ts`, `routes.ts`. 인증 코어의 사용자 잠금/세션 검사를 공유한다. 공개 응답은 모집 메타데이터만 반환한다.
- 멱등 기록은 사용자별 business scope로 method/path/정규화 body를 비교한다. 성공 후 취소/마감되더라도 원래 키는 원래 응답을 재현한다. 최소 90일 또는 최종 접수 종료 다음 날 중 더 늦은 시각까지 보존 대상으로 지정했으며 삭제 worker는 아직 없다.
- 시작 판정은 해당 코호트의 조회/쓰기 시 수행한다. 미달 취소/시작 outbox를 한 번 기록하고, 취소·종료 슬롯은 해당 사용자의 다음 모집 조회/참여 명령에서 정리한다. 전체 코호트의 정시 처리를 보장할 scheduler·안내 발송은 후속이다.
- 참여/취소의 사실·슬롯·성공 응답·감사 이벤트는 같은 transaction에 저장한다. 정원/마감 거부 시 시작 판정과 만료 슬롯 정리만 commit하고, 예상하지 못한 오류는 전체 rollback한다.
- React `/recruitment`: 비회원 모집 조회, 로그인 후 참여 확인, 내 시작 대기, 취소 확인, 페이지 추가 조회, 빈 목록·실패 상태. 실제 계정 화면에 진입 링크 추가.
- 실패 후 수동 재시도는 같은 키를 사용한다. 결과가 불확실한 동안 다른 참여/취소를 차단한다. 요청 키는 해당 화면 메모리에서 유지하며 새로고침 후에는 서버 참여 상태를 다시 읽는다.

## 검증 결과

- Vitest 212개 통과: 기존 인증/데모 회귀 + 모집 UI/클라이언트 8개.
- 실제 PostgreSQL/HTTP 통합 58개 통과: 마지막 자리 경쟁, 동일 사용자 교차 참여, 동시 동일 키·다른 입력 충돌, UUID 정규화, 타인 취소 차단, 최소 인원 취소/outbox 단일 기록, 종료 슬롯 해제, 성공 응답 저장 실패의 전체 rollback.
- DB transaction 판정 시각을 제어해 시작 1ms 전/정각, 최종 접수 종료 정각/1ms 후 검증. 나머지 SQL·잠금·세션 검사는 실제 PostgreSQL을 사용한다.
- 프런트/서버 타입 검사·Vite 및 Vercel 로컬 빌드, API/SPA 산출물 검사, OpenAPI 46개 경로·계약 14개 검증.
- 360/390/430px × 모집·확인·참여 완료·취소 확인·재시도·빈 목록 18개 상태: 가로 넘침 없음, 버튼 44px 이상. 화면 검수는 테스트 API 응답이며 공급자 E2E와 구분한다.
- 테스트 중 DB 시간대에 의존하던 fixture와 시작 판정 SQL의 parameter 타입 문제를 수정하고 전체 통합 테스트를 재실행했다.

## 남은 일

1. 실제 인증·면제권 저장, 홈/기록/피드의 서버 연결.
2. 운영자 모집 개설·취소, 모집/습관 카탈로그 실제 등록. 이번에는 원격 seed나 새 migration을 적용하지 않았다.
3. 최소 시작 인원은 미확정 운영값이다. 화면은 코호트별 `minParticipants`를 표시한다. 테스트의 10명은 확정 운영 정책이 아니다.
4. 실계정 이메일·카카오 검수, 런타임 DB 최소 권한, 공개 조회/업무 명령 남용 제한, 정시 시작 판정 및 outbox 발송/만료 데이터 정리 worker.
5. 기존 개발 도구 취약점 업데이트. 전체 감사/탈퇴·개인정보 삭제 기능은 별도이며 이번 감사 이벤트는 참여/취소에 한정한다.

V1은 변경하지 않았다. 원격 배포·Git 공개 전환·commit/push는 수행하지 않았다.

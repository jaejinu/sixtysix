# 육십육 66일 습관 챌린지 코호트 모바일웹 MVP 통합 명세 v1.0

> 문서명: `sixtysix-project.md`
> 작성일: 2026-09-08
> 상태: 구현 기준 확정 기획·디자인 명세
> 서비스명: 육십육 (영문 표기 `SIXTYSIX`)
> 기준 화면: 430px 모바일 웹
> 구현 대상: HTML, CSS, JavaScript 기반 모바일웹 MVP

## 0. 문서 목적과 우선순위

이 문서는 다음 자료를 비교해 육십육 MVP 구현에 필요한 내용만 통합한 단일 실행 기준이다.

1. `sixtysix-plan.md` — 학생 기획 문서
2. `sixtysix-design-rull.md` — 육십육 전용 디자인 규정
3. `beginner-project.md` — 화면상세 기준 문서(PawMate 통합 명세)
4. `beginner-student.md` — 학생용 실행 지시서

이 문서만으로 서비스 범위, 화면 구조, 컴포넌트, 디자인 토큰 연결, 데이터, 인터랙션, 이미지 연결, 접근성 및 QA 기준을 판단할 수 있어야 한다.

### 0.1 자료 우선순위

충돌할 경우 다음 순서로 적용한다.

1. 접근성과 실제 모바일 웹 동작
2. 사용자가 확인한 화면 대응표, 색상 선택과 핵심 가설
3. 이 통합 명세에서 확정한 제품별 결정
4. `sixtysix-design-rull.md`의 디자인 토큰과 컴포넌트 규정
5. `sixtysix-plan.md`의 서비스 기획과 정책

### 0.2 명칭 규칙

- 서비스 표기는 한글 `육십육`으로 통일한다. UI에 `66데이즈`, `같이66`, `SixtySix`를 혼용하지 않는다.
- 영문 표기가 필요한 경우에만 `SIXTYSIX`를 사용한다.
- `인증`은 사용자가 하루치 습관 실행을 남기는 행위를 뜻하며 다른 이름으로 부르지 않는다.
- `코호트`는 같은 습관·같은 시작일의 30명 그룹을 뜻한다. UI에서는 `코호트`와 `기수`를 함께 쓰지 않는다.
- 면제권, 스트릭, 늦은 인증, 간단 인증, 복귀, 휴면은 모든 화면에서 같은 이름을 사용한다.

### 1.4 기준 화면상세 문서에서 재해석한 내용

- 장소, 병원, 산책코스, 반려견 프로필 콘텐츠는 사용하지 않는다.
- `PawMateHero`는 러닝·반려견 수치를 제거하고 `TodayHero`로 재해석한다.
- `PlaceListCard`는 코호트 목록용 `CohortListCard`와 공지용 `NoticeListCard`로 재해석한다.
- `CareGuideCard`는 세로형 `VerticalMediaCard`로 통합한다.
- `TodayPickCard`는 배지·졸업 오버레이 카드 `BadgeImageCard`로 재해석한다.
- `FeedPost`는 인증 게시물 구조 `CheckinPost`로 사용한다.
- 응급 케어의 안전 문구 구조는 **샘플 데이터 고지와 신고 안내**로 의미를 바꿔 유지한다.
- 저장 화면의 3종 필터·저장 해제·실행 취소 Toast 구조는 **기록 화면 안의 필터**로 옮겨 그대로 유지한다.
- Anton은 기준 문서에서 사용하지 않았지만 육십육에는 D+N·스트릭·66 카운트라는 대형 숫자가 있으므로 디자인 규정 4.1에 따라 사용한다.

## 2. 서비스 정의

### 2.1 한 줄 정의

육십육은 같은 날 시작한 30명 코호트와 함께 하나의 습관을 66일 동안 매일 인증하고 완주하는 습관 챌린지 커뮤니티다.

### 2.2 핵심 메시지

> 66일, 같이 시작한 사람들과 끝까지.

### 2.3 서비스 성격

- 개인 습관 트래커가 아니다. 혼자 체크하는 앱은 이미 많다.
- 채팅방이 아니다. 대화가 아니라 인증이 쌓이는 곳이다.
- 랭킹 경쟁 앱이 아니다. 순위는 보조이고 완주가 목적이다.
- 같은 날 시작한 코호트의 소속감으로 완주율을 만드는 커뮤니티다.

### 2.4 제품 원칙

1. 진행이 항상 보인다. 66칸은 홈과 기록에서 언제나 확인할 수 있다.
2. 끊긴 사람을 내보내지 않는다. 휴면 상태로 남기고 복귀 경로를 제공한다.
3. 규칙은 문장이 아니라 상황으로 설명한다. 정책을 그대로 노출하지 않는다.
4. 인증의 진입 장벽을 낮춘다. 사진이 없어도 인증할 수 있다.
5. 표시로 공정성을 지킨다. 늦은 인증과 간단 인증은 숨기지 않고 구분해 보여준다.

### 2.5 핵심 가설

지시서 13장에 따라 사용자가 확인한 가설이다. 구현 중 임의로 바꾸지 않는다.

| # | 가설 | 화면 반영 |
|---:|---|---|
| 1 | 코호트의 소속감이 개인 스트릭보다 66일 완주율에 더 크게 작용한다 | 홈에서 코호트 오늘 현황을 개인 스트릭보다 큰 비중으로 배치 |
| 2 | "복귀 인증 1회로 재개"라는 명확한 규칙이 있으면 이탈이 줄어든다 | 휴면 상태 홈의 복귀 CTA, 피드·기록의 복귀 표시, 복귀 배지 |
| 3 | 면제권은 자동 소진이 아니라 사용자가 직접 써야 한다 | 끊김 상태 홈의 `면제권 쓰기` 선택과 확인 Modal |
| 4 | 랭킹은 순위보다 완주 페이스로 보여줄 때 서비스 성격과 맞는다 | 랭킹 화면 상단을 오늘 인증 인원과 완주 페이스로 구성, 등수는 보조 표기 |

`[확정 정책]` 사진 인증과 텍스트 인증을 모두 허용하되 피드에서 `간단 인증`으로 구분 표시한다. 기획 단계에서 정책 5로 확정되었으므로 가설이 아니라 결정으로 다룬다.

## 3. 대상 사용자와 해결할 문제

### 3.1 Primary User

- 20~30대 직장인과 취준생
- 습관을 만들고 싶어 챌린지 단톡방에 들어간 경험이 있다
- 인증이 대화에 묻혀 자신의 진행 상황을 알기 어려웠다
- 며칠 빠진 뒤 복귀할 명분을 찾지 못해 조용히 나간 적이 있다
- 하루 15분 내외의 작은 습관을 목표로 한다

### 3.2 핵심 사용자 문제

1. 인증이 채팅에 묻혀 지금까지 며칠 했는지 확인할 수 없다.
2. 며칠 빠지면 복귀할 명분이 없어 그대로 이탈한다.
3. 랭킹과 공지가 수작업이라 유실되고 기준이 불분명하다.
4. 66일이 끝나도 손에 남는 기록이 없다.

### 3.3 제공 가치

| 문제 | 제공 가치 | 화면 |
|---|---|---|
| 진행이 안 보임 | 66칸 진행판과 D+N 히어로로 진행을 항상 노출 | 홈, 기록 |
| 복귀 명분 없음 | 휴면 상태 유지와 복귀 인증 1회 규칙, 면제권 직접 사용 | 홈, 기록 |
| 랭킹·공지 유실 | 자동 산정 랭킹과 공지 목록 | 랭킹, 공지 |
| 끝나도 남는 게 없음 | 완주 배지, 졸업 화면, 다음 코호트 예약 | 졸업, 마이 |
| 소속감 부재 | 코호트 오늘 현황, 스토리 레일, 피드, 응원 | 홈, 피드, 인증 상세 |

## 4. MVP 범위

### 4.1 핵심 화면

전체 MVP는 12개의 논리 화면과 공통 상태로 구성한다. 기준 문서의 8화면에 각각 대응하는 화면을 두고, 육십육의 핵심 흐름에 필요한 4화면을 추가했다.

| # | 화면 | 경로 | 대응하는 기준 화면 | 핵심 역할 | 하단 고정 UI |
|---:|---|---|---|---|---|
| 1 | 온보딩 | `#/onboarding` | 추가 | 습관 선택과 코호트 배정 | 화면 내 CTA |
| 2 | 홈(오늘) | `#/home` | 홈 | 오늘 인증 상태와 다음 행동 제시 | BottomNavigation |
| 3 | 챌린지 탐색 | `#/discover` | 통합 찾기 | 습관·코호트 검색, 필터, 목록 | BottomNavigation |
| 4 | 챌린지 상세 | `#/challenge/:id` | 장소 상세 | 코호트 규칙·기간·멤버 확인과 참여 | StickyActionBar |
| 5 | 오늘 인증 작성 | `#/checkin` | 응급 케어 | 상황 안내 후 인증 입력과 완료 | StickyActionBar |
| 6 | 코호트 피드 | `#/feed` | 커뮤니티 피드 | 코호트 인증 탐색 | BottomNavigation |
| 7 | 인증 상세 | `#/checkin/:id` | 게시글 상세 | 인증 확인, 응원, 저장, 신고 | StickyActionBar |
| 8 | 기록 | `#/record` | 저장 | 66칸 진행판, 통계, 저장한 인증 | BottomNavigation |
| 9 | 마이 | `#/my` | 마이 | 프로필, 배지, 설정 진입 | BottomNavigation |
| 10 | 코호트 랭킹 | `#/ranking` | 추가 | 코호트 완주 페이스와 인증 순위 | BottomNavigation |
| 11 | 공지 | `#/notice` | 추가 | 운영 공지 목록과 상세 | BottomNavigation |
| 12 | 졸업(완주) | `#/graduation` | 추가 | 완주 배지, 여정 요약, 다음 코호트 | StickyActionBar |

로딩, 빈 결과, 이미지 실패, 오류 및 Toast는 별도 페이지가 아니라 해당 화면의 상태로 구현한다.

### 4.2 구현하는 기능

- 하단 내비게이션 화면 전환과 해시 라우팅
- 온보딩 습관 선택과 코호트 배정, 재진입 시 건너뛰기
- 사용자 상태 6개에 따른 홈 화면 변형
- 오늘 인증 작성: 샘플 사진 선택, 한 줄 40자 입력, 공개 범위 선택

- 면제권 사용과 확인 Modal, 잔여 수 갱신
- 복귀 인증과 스트릭 재시작
- 늦은 인증·간단 인증·비공개·복귀 구분 표시
- 코호트 피드 필터와 스토리 레일
- 응원(좋아요)과 저장, 해제, 실행 취소 Toast
- 인증 신고 접수 상태
- 챌린지 검색, 습관 카테고리 필터, 시작일·정원 필터, 정렬
- 코호트 참여와 참여 확인 Modal
- 코호트 랭킹 산정(총 인증 → 동률 시 스트릭)
- 배지 획득 판정과 배지 목록
- 공지 목록과 상세
- 졸업 화면과 다음 코호트 예약
- 설정: 알림 시간, 공개 기본값, 데모 상태 전환
- `localStorage` 상태 유지와 손상 시 기본값 복구
- 빈 상태, 로딩, 오류, 완료 Toast
- 샘플 데이터임을 알리는 안내

### 4.3 구현하지 않는 기능

- 결제, 상금, 환급
- 실제 코호트 매칭 서버와 실시간 동기화
- 신고 검수와 운영자 도구
- 외부 API, 백엔드, 관리자 페이지
- 실제 알림 발송

### 5.3 상세 화면 규칙

- 챌린지 상세, 오늘 인증 작성, 인증 상세, 졸업에서는 BottomNavigation을 숨기고 StickyActionBar를 사용한다.
- 목록 화면으로 돌아갈 수 있는 DetailHeader를 제공한다.
- 브라우저 뒤로 가기와 화면 내 뒤로 가기가 같은 기록 상태를 사용한다.
- 상세 화면 진입 시 최근 본 항목을 기록한다.
- 랭킹과 공지는 DetailHeader와 BottomNavigation을 함께 사용한다. 고정 CTA가 없으므로 중복되지 않는다.

## 6. 화면 명세

각 화면은 지시서 7.2가 요구하는 항목(목적, 진입 경로, 섹션 순서, 표시 정보, 실제 문구, 컴포넌트, CTA, 사용자 행동, 다음 화면, 기본·빈·로딩·오류·완료 상태, 저장 데이터)을 모두 포함한다.

### 6.1 온보딩

#### 목적

첫 진입 사용자가 습관 하나를 고르고 같은 날 시작하는 코호트에 배정되어 첫 화면까지 도달하게 한다.

#### 진입 경로

- 최초 실행 시 `#/onboarding`으로 자동 이동
- 마이 > 설정 > `온보딩 다시 보기`

#### 섹션 순서

1. 진행 Indicator (3단계)
2. `OnboardingSlide` 이미지 영역
3. 단계별 콘텐츠
4. Primary Button

#### 단계별 구성

| 단계 | Eyebrow | 제목 | 설명 | 콘텐츠 | CTA |
|---:|---|---|---|---|---|
| 1 | 66일 습관 챌린지 | 어떤 습관을 66일 동안 이어볼까요? | 하나만 고르면 같은 날 시작하는 코호트에 들어갑니다. | `HabitListItem` 6개 | 이 습관으로 시작하기 |
| 2 | 코호트 배정 | 독서 15분 · 9월 2기에 들어왔어요 | 같은 날 시작한 30명이 함께 66일을 갑니다. 인증 마감은 다음 날 새벽 4시예요. | 코호트 요약 + 멤버 아바타 8개 | 규칙 확인하기 |
| 3 | 규칙 요약 | 끊겨도 돌아올 수 있어요 | 면제권 3회를 직접 쓸 수 있고, 며칠 빠져도 인증 한 번이면 다시 이어집니다. | `PolicyNoteCard` 3개 | 오늘 인증 남기기 |

#### 표시할 정보

- 습관 6종: 이름, 하루 목표 시간, 참여 인원
- 배정 코호트: 이름, 시작일, 종료일, 정원, 현재 인원
- 규칙 3가지: 인증 마감, 면제권, 복귀

#### 실제 문구

- 3단계 규칙 카드 제목과 본문
  - `인증은 다음 날 새벽 4시까지` / `밤에 하는 습관도 그날 인증으로 인정돼요. 새벽 4시가 지나면 12시간 안에 늦은 인증으로 남길 수 있어요.`
  - `면제권은 66일 동안 3번` / `쓸지 말지는 직접 고르면 돼요. 면제권을 쓴 날은 연속 기록이 끊기지 않아요.`
  - `7일 넘게 쉬면 휴면이에요` / `사라지지 않아요. 인증 한 번 남기면 그날부터 다시 이어집니다.`
- 하단 안내: `샘플 데이터로 만든 데모입니다. 실제 코호트 매칭과 알림은 동작하지 않아요. 데모는 23일차부터 시작해요. 처음부터 보려면 마이 화면의 데모 상태 전환에서 0일차를 고르세요.`

#### 주요 컴포넌트

`OnboardingSlide`, `HabitListItem`, `MemberAvatar`, `PolicyNoteCard`, `Button/Primary`

#### CTA

- Primary: 단계별 CTA (위 표)
- Secondary: `건너뛰기` (Text, 우상단, 3단계에서는 표시하지 않음)

#### 사용자 행동

- 습관 하나 선택 (단일 선택, 미선택 시 CTA 비활성)
- 단계 이동, 뒤로 가기
- 건너뛰기 시 기본 습관 `독서 15분`으로 배정

#### 이동할 다음 화면

- 3단계 CTA → `#/checkin`
- 건너뛰기 → `#/home`

#### 상태

| 상태 | 내용 |
|---|---|
| 기본 | 1단계, 습관 미선택, CTA 비활성 |
| 빈 상태 | 없음 (습관 목록은 항상 6개) |
| 로딩 | 코호트 배정 시 CTA 안에 220ms Spinner, 버튼 폭 고정 |
| 오류 | 배정 실패 시 `코호트를 불러오지 못했어요. 다시 시도해 주세요.` + `다시 시도하기` |
| 완료 | 온보딩 완료 플래그 저장 후 재진입 시 홈으로 이동 |

#### 저장되는 데이터

`sixtysix.me.habitId`, `sixtysix.me.cohortId`, `sixtysix.me.onboarded = true`, `sixtysix.me.startedAt`

### 6.2 홈(오늘)

#### 목적

오늘 인증했는지, 지금까지 며칠 왔는지, 코호트가 오늘 어떤 상태인지를 한 화면에서 보여주고 다음 행동을 하나로 좁힌다.

#### 진입 경로

- 온보딩 완료 후
- BottomNavigation 홈 탭
- 인증 완료 후 자동 복귀

#### 섹션 순서

1. `AppHeader`
2. `TodayHero` + Primary Button
3. `HelpQuickMenu` (끊김·휴면 상태에서만)
4. 코호트 오늘 현황

6. `BadgeImageCard` — 이번 주 배지
7. `NoticeListCard` 배너
8. `HabitPreviewCard` Slider — 추천 습관
9. `BottomNavigation`

모든 섹션을 첫 화면에 밀어 넣지 않는다. 첫 화면에는 Header, Hero의 D+N과 다음 행동이 보여야 한다.

#### Header

- 좌측: `육십육` 텍스트 로고, 코랄

#### TodayHero — 사용자 상태 6개별 구성

### 6.4 챌린지 상세

#### 목적

#### 진입 경로

#### RuleInfoCard 4개

| 라벨 | 값 | 설명 |
|---|---|---|

1. `늦어도 괜찮아요` / `새벽 4시가 지나면 12시간 안에 늦은 인증으로 남길 수 있어요. 연속 기록은 이어지고, 피드에는 늦은 인증으로 표시돼요.`

4. `순위보다 완주예요` / `순위는 총 인증 일수로 매겨요. 같으면 연속 기록이 앞섭니다. 목적은 66일을 끝까지 가는 거예요.`

#### 표시할 정보

코호트명, 습관명, 하루 목표, 시작일, 종료일, 현재 인원/정원, D-Day, 멤버 8명, 규칙 4가지

#### 실제 문구

### 6.5 오늘 인증 작성

#### 목적

오늘 무엇을 했는지 사진과 한 줄로 남기고, 공개 범위를 정한 뒤 인증을 확정한다.

#### 진입 경로

홈 Primary CTA / 피드 빈 상태 CTA / 기록 오늘 칸 안내 / 챌린지 참여 직후

#### 섹션 순서

1. `DetailHeader` — 제목 `오늘 인증`
2. 날짜와 D+N (Anton 96px)
3. 상황 안내 Banner
4. 사진 선택 Grid
5. 선택한 사진 미리보기
6. `OneLineInput` — 한 줄 40자
7. 공개 범위 선택 Row
8. `StickyActionBar` — `인증 남기기`

#### 상황 안내 Banner

기준 문서 응급 케어의 안전 안내 Banner를 육십육의 상황 안내로 바꿔 유지한다.

| 상황 | 문구 |
|---|---|
| 정상 시간 | `오늘 9월 8일 인증이에요. 마감은 내일 새벽 4시입니다.` |
| 마감 후 12시간 이내 | `새벽 4시가 지났어요. 지금 남기면 늦은 인증으로 기록되고 연속 기록은 이어져요.` |
| 복귀 | `8일 만이에요. 이번 인증부터 다시 1일차로 이어집니다.` |
| 이미 완료 | `오늘 인증은 이미 남겼어요. 내용을 고치려면 기록에서 수정하세요.` |

#### 사진 선택

- 습관에 맞는 샘플 사진 5장을 3열 Grid `110×110px`로 제공한다.
- 독서 코호트 기본 제공: `habit-reading`, `habit-journal`, `habit-english`, `habit-water`, `habit-stretch`
- 선택하지 않아도 제출할 수 있고 이 경우 `간단 인증`으로 저장된다.
- 선택한 사진은 `394×250px`로 미리보기하고 `선택 해제` Text Button을 제공한다.

#### 한 줄 입력

- placeholder: `오늘 무엇을 했는지 한 줄로 남겨보세요`
- 최대 40자, 남은 글자 수 실시간 표시
- 빈 입력 제출 불가

#### 공개 범위

| 선택 | 라벨 | 설명 |
|---|---|---|
| 기본 | 코호트에 공개 | 우리 코호트 30명이 볼 수 있어요 |
| 선택 | 나만 보기 | 피드에는 안 보이고 기록과 순위에는 들어가요 |

#### 실제 문구

- 오류: `한 줄을 남겨야 인증할 수 있어요.` / `40자까지만 쓸 수 있어요. 8자를 줄여주세요.`
- 완료 화면 제목: `23일차 인증을 남겼어요`
- 완료 설명: `오늘 코호트 18명이 함께했어요. 연속 10일째예요.`
- 완료 CTA: `코호트 피드 보기`, 보조 `홈으로 돌아가기`
- 안내: `사진은 샘플 이미지 중에서 고릅니다. 실제 촬영과 업로드는 이 데모에 없어요.`

#### 주요 컴포넌트

`DetailHeader`, `CheckinComposer`, `OneLineInput`, `Badge/Status`, `Toggle`, `StickyActionBar`, `Toast`

#### CTA

- Primary: `인증 남기기`
- Secondary: `선택 해제`, 완료 후 `홈으로 돌아가기`

#### 사용자 행동

- 샘플 사진 선택·해제
- 한 줄 입력
- 공개 범위 전환
- 인증 제출 (중복 제출 차단)

#### 이동할 다음 화면

완료 상태 → `#/feed` 또는 `#/home`

#### 상태

| 상태 | 내용 |
|---|---|
| 기본 | 사진 미선택, 빈 입력, 공개 범위 `코호트에 공개`, CTA 비활성 |
| 빈 상태 | 해당 없음 |
| 로딩 | 제출 중 CTA 안에 Spinner, 폭 고정, 재클릭 차단 |
| 오류 | 입력 검증 오류를 입력 아래 `fa-circle-exclamation`과 함께 표시 |
| 완료 | 같은 화면이 완료 상태로 전환. D+N, 한 줄, 상태 배지, 다음 행동 2개 표시 |

## 7. 디자인 시스템 연결

이 장은 `sixtysix-design-rull.md`의 요약이다. 값이 충돌하면 디자인 규정 문서를 따른다.

### 7.1 앱 셸

| 화면 구간 | 좌우 여백 | 콘텐츠 폭 |
|---|---:|---:|
| 360~389px | 16px | `100% - 32px` |
| 390~430px | 18px | `100% - 36px` |
| 431px 이상 | 중앙 430px 셸 | 최대 394px |

- 앱 최대 폭은 `430px`이다.
- 앱 배경은 웜 화이트 라이트 테마이며 큰 화면에서는 430px 셸을 중앙 배치한다.
- 피드 인증 이미지와 저장 인증 Grid만 필요 시 430px 풀블리드로 표시한다.
- 66칸 진행판은 394px 콘텐츠 폭을 사용한다.
- 의도하지 않은 페이지 전체 수평 스크롤은 금지한다.
- iOS 상태바와 Home Indicator를 웹 DOM으로 그리지 않는다.
- Safe Area는 `env(safe-area-inset-*)`로 처리한다.

### 7.2 필수 컬러 토큰

사용자가 확정한 세 색상과 그 파생값만 사용한다. 전체 토큰은 디자인 규정 3장에 있다.

```css
:root {
  --color-bg-app: #fbf8f2;          /* 배경 컬러 */
  --color-brand-primary: #f04e2c;   /* 대표 컬러 */
  --color-accent: #1f6f5f;          /* 액센트 컬러 */

  --color-brand-pressed: #c63a1e;
  --color-brand-text: #c63a1e;
  --color-text-on-brand: #1a1a1a;

  --color-bg-surface: #ffffff;
  --color-bg-surface-subtle: #f1eee8;
  --color-border-default: #e4e0d8;

  --color-text-primary: #1a1a1a;
  --color-text-secondary: #4a4a4a;
  --color-text-muted: #6e6e6e;

  --color-success: #1f6f5f;
  --color-warning: #ffcc00;
  --color-danger: #b3261e;
}
```

- 대표 컬러 배경 위 텍스트는 `#1A1A1A`를 사용한다.
- 대표 컬러를 텍스트로 쓸 때는 `#C63A1E`를 사용한다.
- 액센트 컬러는 인증 완료·복귀·성공에만 사용한다.
- 파스텔 계열을 추가하지 않는다. 연한 면은 `#F1EEE8`과 `#E4E0D8`만 사용한다.

```css
:root {

  --font-size-card-title: 20px;
  --font-size-body: 16px;
  --font-size-label: 14px;
  --font-size-meta: 12px;

```

- 화면 제목: 24~30px, 600
- 섹션 제목: 24px, 600
- 카드 제목: 20px, 500~600
- 본문과 CTA: 16px, 400~600
- 라벨: 14px, 메타: 12px
- D+N, 스트릭, 총 인증, 66 카운트는 Anton
- 10px와 11px 텍스트를 사용하지 않는다.

### 7.4 간격과 라운드

```css
:root {
  --space-page-x: 18px;
  --space-section-y: 48px;
  --space-slider-gap: 12px;

  --radius-xs: 4px;
  --radius-sm: 8px;
```

- Header 아래 첫 콘텐츠: `27~31px`
- 홈 주요 섹션 간격: `48px`
- SectionHeader와 콘텐츠: `15px`
- Slider 카드 간격: `12px`
- 세로 목록 간격: `10~12px`
- 66칸 타일 라운드: `4px`

### 7.5 아이콘과 모션

- 프로젝트 전체의 기능 아이콘은 **Font Awesome**으로 통일한다.
- CSS 도형, 이모지, 텍스트 특수문자 또는 임의 SVG를 기능 아이콘으로 사용하지 않는다.
- 기능별 고정 아이콘은 디자인 규정 5.3의 표를 따른다.
- 기본 시각 크기는 `24px`, 터치 영역은 최소 `44×44px`이다.
- 눌림 `120ms`, 상태 전환 `220ms`, 화면·Modal `220~360ms`
- `prefers-reduced-motion: reduce`에서는 자동 이동과 큰 애니메이션을 제거한다.

| 마이 | 2(프로필 아바타) |
| 랭킹 | 멤버 아바타(2, 3, 4, 5, 6, 9) |
| 공지 | 7, 10, 8 |
| 졸업 | 8(완주 배지), 저장 인증 사진 |

### 9.3 이미지 생성 규칙

- 이미지 생성 도구로 정확히 10장을 생성한다.
- 이미지 검색 결과나 외부 이미지 URL로 대체하지 않는다.
- 생성 이미지는 `assets/images/`에 저장하고 코드에서 상대 경로로 불러온다.
- 이미지 안에 UI 문구, 로고, 읽어야 하는 텍스트를 생성하지 않는다.
- 손, 얼굴, 사물이 심하게 왜곡된 결과는 사용하지 않는다.
- 같은 이미지의 단순 크롭본을 서로 다른 이미지로 계산하지 않는다.
- 필요 이상으로 장식적인 AI 이미지 스타일을 적용하지 않는다.
- WebP로 저장하고 카드 용도에 맞는 비율과 안전 영역을 확보한다.
- 적용된 실제 규격: 가로 `1100×689`, 세로 `900×1125`, 품질 82, 10장 합계 약 596KB.

### 9.4 이미지 구현 규칙

- `object-fit: cover`를 기본으로 하고 컨테이너에 `aspect-ratio`를 지정한다.
- Hero와 세로 카드에서 피사체가 잘리지 않도록 이미지별 `object-position`을 지정한다.
- 같은 이미지를 관련 없는 두 섹션에 반복 사용하지 않는다.
- 같은 인증의 피드 카드와 상세 화면은 같은 이미지를 사용한다.
- 인증에 사진이 없으면(간단 인증) 스토리 레일과 피드 모두 사진 없이 남긴 한 줄을 보여준다. 다른 이미지로 자리를 채우지 않는다.
- 모든 의미 있는 이미지에 구체적인 한국어 `alt`를 제공한다.
- 카드 텍스트와 같은 의미를 반복하는 썸네일은 `alt=""`로 처리한다.
- 이미지 실패 시 카드 크기와 텍스트 구조를 유지하는 대체 Surface를 표시한다.
- 첫 Hero 이미지만 우선 로드하고 나머지는 `loading="lazy"`를 사용한다.
- 회색 임시 상자를 정상 상태의 placeholder로 남기지 않는다.

### 9.5 이미지 생성 프롬프트

기획 8장의 결정에 따라 프롬프트는 이 문서에 작성하고 생성은 이미지 생성 도구로 수행한다. 프롬프트 전문은 `assets/images/IMAGE-PROMPTS.md`에 둔다.

## 11. 인터랙션 규칙

### 11.1 Slider

- CSS Scroll Snap을 우선한다.
- 터치 드래그, 트랙패드 및 키보드 입력을 지원한다.
- 마지막 카드 뒤에 불필요한 빈 영역이 없어야 한다.
- Slider 컨테이너만 가로 스크롤되어야 한다.
- 현재 위치와 전체 개수를 접근 가능한 텍스트로 전달한다.
- 자동재생을 사용하지 않는다.

### 11.2 응원과 저장

- 상태 변경 버튼은 `button`을 사용한다.
- `aria-pressed`를 실제 상태와 동기화한다.
- 상태 변경 직후 아이콘, 라벨, 수치와 Toast를 함께 갱신한다.
- 저장 해제 후 5초 이내 Toast Action으로 실행 취소를 제공한다.
- 빠른 연속 클릭으로 수치가 잘못 증가하지 않게 한다.

### 11.3 인증 제출

- 제출 중 버튼을 비활성화하고 중복 제출을 차단한다.
- 제출 성공 시 홈, 피드, 기록, 랭킹의 파생 값을 한 번에 재계산한다.
- 66칸 진행판 갱신은 220ms 전환을 사용하고 Live Region으로 알린다.
- 배지 획득 조건을 제출 직후 판정하고 획득 시 Toast로 알린다.
- 실패 시 입력값을 유지한 채 오류를 표시한다.

### 11.4 면제권과 복귀

- 면제권 사용은 확인 Modal을 거친다.
- 사용 후 잔여 수, 스트릭, 66칸 표시를 즉시 갱신한다.
- 면제권이 0회면 메뉴를 비활성으로 두고 `면제권을 모두 썼어요`를 설명으로 표시한다.
- 휴면 상태에서는 면제권을 쓸 수 없고 복귀 인증만 가능하다.
- 복귀 인증 성공 시 스트릭을 1로 설정하고 총 인증은 유지한다.

### 11.5 검색과 필터

- 입력 후 250ms Debounce 필터링을 사용한다.
- 검색어와 선택 필터를 동시에 적용한다.
- 선택된 필터는 화면을 이동했다 돌아와도 유지한다.
- 초기화는 한 번의 선택으로 검색어와 모든 조건을 해제한다.
- 결과가 없으면 이유와 초기화 CTA를 제공한다.

### 11.6 화면 전환

- 링크 이동은 `a`, 상태 변경은 `button`을 사용한다.
- 클릭 가능한 `div`를 만들지 않는다.
- 카드 전체 링크 안에 별도 버튼을 중첩하지 않는다.
- 해시 라우팅을 사용하고 브라우저 뒤로 가기 기록을 깨뜨리지 않는다.
- 화면 전환 시 제목으로 포커스를 이동한다.
- 상세 화면 진입 시 최근 본 항목을 기록한다.

## 12. 접근성과 안전

- 논리 화면마다 하나의 H1을 사용한다.
- 제목 단계를 건너뛰지 않는다.
- 모든 인터랙션 요소는 키보드 포커스를 받을 수 있어야 한다.
- Focus Ring은 최소 2px이며 제거하지 않는다.
- 터치 영역은 최소 `44×44px`이다.
- 일반 본문 대비는 최소 4.5:1, 큰 텍스트와 UI 경계는 최소 3:1이다.
- 대표 컬러와 액센트 컬러로 표현한 상태는 라벨 또는 아이콘을 함께 사용한다.
- 66칸 진행판은 `role="img"`와 요약 `aria-label`, 텍스트 범례를 함께 제공한다.
- 200% 글자 확대에서도 인증 남기기와 피드 탐색을 완료할 수 있어야 한다.
- `prefers-reduced-motion`을 존중한다.
- Modal은 Focus Trap, Escape 닫기, 닫은 후 Focus 복귀를 지원한다.
- 인증 완료, 응원, 저장, 오류는 Live Region으로 알린다.

### 12.1 안전과 고지

기준 문서의 응급 케어 안전 규칙을 육십육의 맥락으로 바꿔 유지한다.

- 모든 인원, 인증, 순위, 공지는 샘플 데이터이며 화면에 그 사실을 표시한다.
- 실제 코호트 매칭, 알림 발송, 사진 업로드가 없다는 점을 온보딩과 마이에 명시한다.
- 신고는 접수 상태까지만 제공하고 검수 결과를 임의로 만들지 않는다.
- 다른 사용자의 인증 내용을 실제 인물의 기록처럼 표현하지 않는다.
- 습관 실행에 대한 의학적·건강상 조언을 제공하지 않는다.

- Header, Nav, Main, Section, Article, List 등 의미 있는 요소를 사용한다.

- Font Awesome은 CDN이 아니라 로컬 또는 공식 배포 링크 중 하나를 프로젝트 전체에 일관되게 사용한다.

### 13.3 CSS

- 이 문서와 디자인 규정의 토큰을 사용한다.

- 앱 셸 전체에 `overflow-x: auto`를 적용하지 않는다.
- `100vh`보다 `100dvh`를 우선한다.
- 텍스트 컨테이너에 불필요한 고정 높이를 사용하지 않는다.
- 미디어와 버튼처럼 크기 계약이 있는 요소에만 고정 높이를 사용한다.

### 13.4 JavaScript

- 화면, 필터, 인증, 응원, 저장이 하나의 상태 모델을 사용한다.
- UI를 다시 그린 뒤 이벤트가 중복 등록되지 않게 위임을 사용한다.
- 빠른 연속 클릭으로 수치가 잘못 증가하지 않게 한다.
- 데이터 오류가 전체 내비게이션을 막지 않게 한다.
- 실제 업로드, 알림, 매칭이 없는 부분은 실패한 척하지 않고 명시적인 데모 상태로 처리한다.
- 파생 값(스트릭, 총 인증, 순위, 배지)은 저장하지 않고 인증 목록에서 계산한다. 단, 데모 초기값은 예외로 저장한다.

## 14. 금지 규칙

- 데스크톱 대시보드나 표 중심 레이아웃으로 만들지 않는다.
- 절대좌표를 화면 전체에 복사하지 않는다.
- iOS 상태바와 Home Indicator를 웹 UI로 그리지 않는다.
- 대표 컬러와 액센트 컬러를 장식 목적으로 남용하지 않는다.
- 대표 컬러 배경 위에 흰 텍스트를 사용하지 않는다.
- 사용자가 선택하지 않은 파스텔 계열을 추가하지 않는다.
- 10px와 11px 일반 텍스트를 사용하지 않는다.
- 이모지 아이콘을 사용하지 않는다.
- 같은 역할의 카드에 임의의 라운드와 간격을 새로 만들지 않는다.
- 이미지 위 텍스트를 가독성 처리 없이 배치하지 않는다.
- 자동 Slider를 만들지 않는다.
- BottomNavigation과 StickyActionBar를 동시에 표시하지 않는다.
- 66칸 타일을 44px 미만 크기로 클릭 대상으로 만들지 않는다.
- 샘플 인원과 인증을 실제 사용자 기록처럼 표현하지 않는다.
- 신고 결과와 운영 처리 내용을 임의로 만들지 않는다.
- 외부 이미지 URL에 의존하지 않는다.
- 사각 박스에 텍스트만 넣은 카드뉴스를 반복 배치하지 않는다.
- 기능처럼 보이는 버튼을 눌러도 아무 반응이 없게 두지 않는다.

### 15.8 자동 회귀 테스트

위 시나리오는 `../qa` 의 Playwright 테스트로 구현되어 있다. 배포 대상 폴더 바깥에 두어 정적 배포에 영향을 주지 않는다.

```bash
cd qa
npm install && npx playwright install chromium   # 처음 한 번
npm test                                          # 360 · 390 · 430px 전부 실행
```

| 파일 | 검증 내용 |
|---|---|
| `tests/flows.spec.js` | 15.7 시나리오 1~8, 10 |
| `tests/layout.spec.js` | 12화면 구조·접근성, 앱 셸 폭, 고정 UI 겹침, 탭 활성, 에셋 연결, 색상 토큰 |
| `tests/assets.spec.js` | 생성 이미지 10장의 존재와 정상 렌더 |
| `tests/visual.spec.js` | 390 · 430px 스크린샷 회귀 (이미지가 있을 때만 실행) |

이미지 10장을 넣기 전에는 `tests/assets.spec.js` 만 화면 폭마다 실패한다. 이 실패가 남은 작업을 알려주는 게이트다. 이미지 404 는 콘솔 오류 집계에서 제외하므로 나머지 검사는 정상 동작한다.

## 16. MVP 완료 정의

다음 조건을 모두 만족하면 육십육 모바일웹 MVP가 완료된 것으로 본다.

- 이 문서의 12개 논리 화면을 구현했다.
- 4개 BottomNavigation이 실제로 동작하고, 탭이 없는 화면에 진입 경로가 있다.
- 온보딩 → 인증 → 홈 갱신의 핵심 흐름을 완주할 수 있다.
- 홈이 사용자 상태 6개에 따라 다르게 보이고 데모 전환 수단이 있다.
- 66칸 진행판이 인증 수만큼 채워지고 오늘 인증 후 즉시 1칸 늘어난다.
- 늦은 인증·간단 인증·비공개·복귀가 피드와 기록에서 구분 표시된다.
- 면제권 사용 시 스트릭 유지와 잔여 감소가 즉시 반영된다.
- 정책 10개가 챌린지 상세 규칙 섹션에 사용자 언어로 요약돼 있다.
- 코호트 피드, 인증 상세, 응원과 저장이 동작한다.
- 랭킹이 총 인증 → 스트릭 순으로 계산되고 완주 중심으로 표시된다.
- 로컬 이미지 10장을 사용하고 외부 이미지에 의존하지 않는다.
- 라이트 웜 화이트 배경, 코랄 Primary, 딥 그린 완료 상태, Pretendard와 Anton, 430px 셸을 일관되게 사용한다.
- 선택하지 않은 파스텔톤이 없고 연한 보조면은 밝은 회색 계열만 사용한다.
- 360px, 390px, 430px에서 레이아웃을 검증했다.
- Empty, Loading, Error 및 이미지 실패 상태가 있다.
- 인증, 응원, 저장, 설정이 `localStorage`에 유지된다.
- 터치 영역, 대비, 키보드, 대체 텍스트와 모션 감소를 검증했다.
- BottomNavigation과 StickyActionBar가 콘텐츠를 가리지 않는다.
- 최소 3회의 테스트·수정·회귀 테스트를 완료했고 콘솔 오류가 없다.
